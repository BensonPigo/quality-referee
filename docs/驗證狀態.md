# 驗證狀態

## 自動化測試

| 項目 | Windows | macOS（arm64） | ubuntu（GitHub Actions） |
|---|---|---|---|
| 單元測試（`python -m unittest`） | ✓ | ✓ | ✓ |
| selftest 的 Go 範例情境（含 gate.sh） | ✓ | ✓ | ✓ |
| selftest 的 C# 範例情境（含照 README 掛上、gate.sh），.NET SDK 10 | ✓ | ✓ | ✓ |

Windows 用 Git for Windows 的 bash，macOS 用系統的 bash 3.2。ubuntu 是每次推送和 PR 時跑的 `.github/workflows/selftest.yml`。

## 實際使用

| 項目 | Go | C# |
|---|---|---|
| 照 README 掛進專案，三關判定符合預期 | ✓ 真實專案（BeThere，module 範圍） | 只在為了驗證另外建的專案上（macOS），真實專案還沒有 |
| Claude Code 實際觸發 Stop hook，gate.sh 擋下 | ✓ | ✓（同上，另外建的專案） |
| workflow 範本在 GitHub Actions 上跑三關 | ✓ ubuntu-latest，數字和本機一致 | 還沒有 |
| 量測結果和別的來源對得上 | ✓ 和 quality-tools v2.4.0 對照：範例專案的 CRAP 表和抓錯計數（package、module 兩種範圍）、BeThere 的 CRAP 表和一個套件的抓錯計數 | ✓ 複雜度和手算的一樣 |
| 工具的建置不受專案設定影響 | — | ✓ 快取目錄放在塞了惡意設定檔的目錄底下，照樣建置成功 |

## 還沒驗證

- C# 檢查員在真實專案上試點；`templates/csharp/workflows/csharp.yml` 在 runner 上跑。
- C# 檢查員在 .NET 6～9 的 SDK 上跑（selftest 用 .NET 10）。
- CI 實際擋下 PR（結束碼 1 讓 workflow 失敗）。結束碼 1 在本機和 selftest 都驗證過，但還沒在 runner 上發生過。
- Gitea 的 act_runner 支不支援範本用的 v7 actions（Node 24）。
