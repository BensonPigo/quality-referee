# 已知限制

三道關的判定規則本身看不到的情況。其他限制各自寫在相關的文件：

- 繞過檢查的改法，哪些擋得住、哪些要靠人審：[鎖定規則.md](鎖定規則.md) 的「還擋不住的」。
- 量測工具的限制：[Go檢查員.md](Go檢查員.md)、[CSharp檢查員.md](CSharp檢查員.md) 的「限制」。

- 完全沒有測試的專案，第一關會通過：`go test ./...`、`dotnet test` 在沒有任何測試時結束碼是 0。
- 「新寫的程式沒附測試」不一定會被第二關擋下。新程式如果在既有測試會走到的路徑上，覆蓋率一開始就是 100%，CRAP 只看複雜度。這時要靠第三關的抓錯率，看既有測試有沒有真的驗證新程式的行為。
- 抓錯率和測到率是所有改到的行合起來算的比例。一個函式完全沒被測到時，比例可能照樣過門檻，這種情況由「每個函式至少抓到一個」擋下。但這條規則只要求一個：函式只測了一條路徑、或測試沒有斷言但改壞後剛好當掉或逾時，都算抓到。測試夠不夠還是要靠兩個比例和人看。
- 「每個函式至少抓到一個」只在第三關判定，gate.sh 不跑第三關，AI 回覆結束時擋不到，要等 CI。
- 不在任何函式範圍裡的程式（套件層的變數初始化、C# 的頂層陳述式）不參與「每個函式至少抓到一個」。
- 覆蓋率跟執行的平台有關。測試檔有 build constraint（例如 `//go:build !windows`）時，那些測試在別的平台不會跑，被它們測到的函式覆蓋率就不同，CRAP 也跟著不同。實際遇過：同一個 base 下，沒改到但超標的函式數在本機 Windows 和 CI 的 ubuntu 差一個。以 CI 的結果為準。
