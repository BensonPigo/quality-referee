# 合約（第一版）

裁判和檢查員之間的介面。裁判不認得任何語言，也不呼叫任何量測工具，只做三件事：執行設定檔寫的指令、讀檢查員交出的記分表、依門檻判定。這份文件定下來之後，改任何欄位都要升版本（`schema` 字串結尾的數字）。

參考實作：路徑比對在 `referee/paths.py`，記分表驗證在 `referee/sheets.py`，報告驗證在 `referee/schema.py`。檢查員可以直接抄 `paths.py`。

## 檢查員的呼叫方式

裁判用設定檔裡的指令（字串陣列，不經過 shell）啟動檢查員，工作目錄是專案根目錄，在原有環境變數之外多傳兩個：

| 環境變數 | 內容 |
|---|---|
| `REFEREE_OUT` | 記分表要寫到哪個檔案（裁判建的暫存檔路徑，檔案一開始不存在） |
| `REFEREE_CONTEXT` | 一個 JSON 檔的路徑（裁判建的暫存檔），內容見下 |

檢查員的結束碼：0 是量完了；其他值是量測失敗，裁判以結束碼 2 停下，印出檢查員的輸出（stdout 和 stderr 合併，最後 40 行）。記分表不存在、不是合法 JSON、格式不符，也是結束碼 2，訊息指出哪一項哪個欄位錯。

### context

```json
{"schema": "referee.context/1",
 "gate": "crap",
 "sources": ["**/*.go"], "tests": ["**/*_test.go"], "exclude": ["vendor/", "tools/"],
 "changed_files": null}
```

- `gate`：`crap` 或 `mutation`。
- `sources`、`tests`、`exclude`：原樣抄自 `.referee.json`。檢查員要跳過的目錄（例如 Go 不跑 vendor 底下的套件）讀這裡，不用在指令參數再寫一次。
- `changed_files`：只有 `mutation` 加 `--base` 時才是改到的原始碼檔案清單（依本文的範圍規則篩過，不含測試檔，排序過），其他情況都是 `null`。檢查員可以只量這些檔案來省時間，也可以忽略它。`crap` 的檢查員永遠拿到 `null`，一律量整個專案，裁判才算得出「沒改到但超過門檻」的函式數。

## 路徑比對規則

裁判和檢查員都照這個規則。

- 路徑一律相對於專案根目錄、用 `/` 分隔，大小寫有別。
- `sources`、`tests` 是樣式：`*` 比對任意個非 `/` 的字元；`?` 比對一個非 `/` 的字元；`**/` 比對零層或多層目錄，所以 `**/*.go` 比得到根目錄的 `main.go`，也比得到 `a/b/c.go`。`**` 出現在 `**/` 以外的位置，比對任意字元（含 `/`）。其餘字元照字面比對。
- 在範圍內 = 比得到任何一個 `sources` 樣式，而且比不到任何一個 `tests` 樣式，而且不在 `exclude` 底下。
- `exclude` 是目錄：路徑等於它，或以「它 + `/`」開頭，就算在底下（結尾的 `/` 可寫可不寫）。`vendor` 底下的是 `vendor/x.go` 和 `vendor` 本身，不含 `vendors/x.go`。

範例（`sources` 是 `**/*.go`，`tests` 是 `**/*_test.go`，`exclude` 是 `vendor/`）：`main.go`、`a/b.go` 在範圍內；`a/b_test.go`、`vendor/x.go`、`vendor` 不在。

## 裁判一律再篩一次

不論有沒有 `--base`，裁判拿到記分表後，先丟掉不在範圍內的項目（不在 `sources`、在 `tests`、或在 `exclude` 底下），再判定。加 `--base` 時，再依改到的行篩：`crap` 只留行範圍和改到的行有交集的函式，`mutation` 只留所在行改到的改壞版本。檢查員多交了東西不影響結果。

改到的行的算法：起點是 `base` 和 `HEAD` 的分岔點（`git merge-base`），終點是工作目錄，所以還沒 commit 的改動和新增（untracked）的檔案也算；`git diff -U0 --ignore-cr-at-eol`，只差換行字元（CRLF 和 LF）不算改動；只刪除沒新增的 hunk，記成刪除位置前後兩行；新增的檔案整個算改到。

## 函式表（`referee.functions/1`）

```json
{"schema": "referee.functions/1",
 "tools": {"gocyclo": "v0.6.0"},
 "functions": [{"file": "shipping/fee.go", "name": "Fee", "start": 3, "end": 9, "complexity": 3, "coverage": 0.75}]}
```

| 欄位 | 規則 |
|---|---|
| `schema` | 必填，必須是 `referee.functions/1` |
| `functions` | 必填，陣列，每一項的六個欄位都必填，不能多出別的欄位 |
| `tools` | 選填，物件，值是字串（工具名稱 → 版本）；沒給當作 `{}` |
| `settings` | 選填，見下 |
| `file` | 非空字串，相對專案根目錄、用 `/` 分隔（不能有 `\`、開頭的 `/` 或 `./`、磁碟機代號、`..`） |
| `name` | 非空字串 |
| `start`、`end` | 正整數，`start <= end` |
| `complexity` | 正整數 |
| `coverage` | 0～1 的數字 |

CRAP = `complexity² × (1 − coverage)³ + complexity`，由裁判計算，檢查員不交。大於門檻才算超標（等於不算）。超標函式的改善方向：`complexity` 大於門檻時只能拆函式；否則算出覆蓋率要補到幾 %。

## 改壞版本表（`referee.mutants/1`）

```json
{"schema": "referee.mutants/1",
 "tools": {"gremlins": "v0.6.0"},
 "mutants": [{"file": "shipping/fee.go", "line": 5, "column": 11, "mutator": "CONDITIONALS_BOUNDARY",
              "status": "LIVED", "original": ">=", "replacement": ">"}]}
```

| 欄位 | 規則 |
|---|---|
| `mutants` | 必填，陣列 |
| `file` | 同函式表 |
| `line` | 正整數，從 1 起算 |
| `column` | 選填，正整數，從 1 起算，檢查員回報什麼就是什麼（含縮排） |
| `mutator` | 非空字串，檢查員自己的改法名稱 |
| `status` | `KILLED`、`TIMED_OUT`、`LIVED`、`NOT_COVERED`、`NOT_VIABLE`、`SKIPPED` 其中之一。`EQUIVALENT`、`EXCLUDED_MUTATOR` 由裁判標記，檢查員交上來是格式錯誤 |
| `original`、`replacement` | 選填，字串（`replacement` 可以是空字串，代表刪掉） |

`line_text`（該行原文去頭尾空白）由裁判依檔案內容填，不在記分表裡，交上來是格式錯誤。

- 抓錯率 = (`KILLED` + `TIMED_OUT`) ÷ (`KILLED` + `TIMED_OUT` + `LIVED`)：有測到的改壞版本裡，抓到幾成。低於 `kill_rate_threshold` 就沒過。
- 測到率 = (`KILLED` + `TIMED_OUT` + `LIVED`) ÷ (以上加 `NOT_COVERED`)：全部改壞版本裡，有幾成被測試跑到。低於 `reach_rate_threshold` 就沒過。
- `EQUIVALENT`、`EXCLUDED_MUTATOR`、`NOT_VIABLE`、`SKIPPED` 都不算進這兩個比例。分母是 0 時比例是 `null`，不判定。
- `exclude_mutators` 裡的名稱（比對 `mutator`）一律標成 `EXCLUDED_MUTATOR`，不看原本的狀態。

### 排除清單（`equivalents_file`，預設 `.referee-equivalents.json`）

陣列，每一項：`file`、`mutator`、`line_text`、`reason`、`approved_by` 必填（非空白字串），`function`（字串，只顯示不比對）、`column`（正整數）選填。比對鍵是 `file` + `mutator` + `line_text`（去頭尾空白），不用行號。沒有 `column` 的項目對整行；有 `column` 的只對那一欄（值照記分表的 `column`）。對得上的改壞版本標成 `EQUIVALENT`。有 `--base` 時，「沒用到」只算 `file` 在這次改到的檔案裡的項目；對得上全部量到的改壞版本（含沒改到的行）都算有用到。檔案不存在等於空清單。

## 選填的 `settings`

兩種記分表都可以帶 `settings`（物件，值是字串、數字、布林或 null），寫檢查員這次實際生效的設定，例如 `{"workers": 4, "coverage_scope": "module"}`。裁判不解讀，原樣放進報告，文字輸出印成「檢查員設定：workers 4、coverage_scope module」；沒有就印「檢查員設定：無」。

## JSON 報告（`referee.report/1`）

`crap --json`、`mutation --json`、`test --json`、`check --json 目錄` 共用同一個格式。`command` 只會是 `test`、`crap`、`mutation`。

```json
{"schema": "referee.report/1", "referee_version": "0.1.0",
 "command": "mutation", "base": "origin/main", "result": "fail",
 "inspector": {"command": ["python", "..."], "tools": {"gremlins": "v0.6.0"}, "settings": {"workers": 4}},
 "crap": null,
 "mutation": {"kill_rate_threshold": 80, "reach_rate_threshold": 50, "exclude_mutators": [],
              "counts": {"KILLED": 3, "TIMED_OUT": 0, "LIVED": 1, "NOT_COVERED": 0, "EQUIVALENT": 0,
                         "EXCLUDED_MUTATOR": 0, "NOT_VIABLE": 0, "SKIPPED": 0},
              "kill_rate": 75.0, "reach_rate": 100.0,
              "packages": {"shipping": {"KILLED": 3, "TIMED_OUT": 0, "LIVED": 1, "NOT_COVERED": 0, "EQUIVALENT": 0,
                                        "EXCLUDED_MUTATOR": 0, "NOT_VIABLE": 0, "SKIPPED": 0}},
              "mutants": [{"file": "shipping/fee.go", "line": 5, "column": 11, "mutator": "CONDITIONALS_BOUNDARY",
                           "status": "LIVED", "original": ">=", "replacement": ">", "line_text": "if total >= 1000 {"}],
              "unused_equivalents": []}}
```

| 欄位 | 規則 |
|---|---|
| `schema` | `referee.report/1` |
| `referee_version` | 裁判版本字串 |
| `command` | `test`、`crap`、`mutation` |
| `base` | 字串或 `null`。`crap`、`mutation` 沒加 `--base` 時是 `null`；`check` 把 `--base`（或設定檔的 `base`）傳給 `crap`、`mutation`；`test` 的報告一律是 `null`（單元測試不看 base） |
| `result` | `pass`、`fail`、`skipped`（該關沒啟用或被 `--skip`） |
| `inspector` | `skipped` 時是 `null`。`test`：`{"command": test.command}`，沒有 `tools`、`settings`。`crap`、`mutation`：`command`（設定檔的指令陣列）、`tools`（記分表的 `tools`，沒有是 `{}`）、`settings`（記分表的 `settings`，沒有是 `null`） |
| `crap` | 只有 `command` 是 `crap` 而且 `result` 不是 `skipped` 時有值，其他情況是 `null` |
| `mutation` | 同上，對應 `mutation` |

`crap` 區塊：`threshold`；`functions`（篩過、有 `--base` 時只含改到的函式，由 CRAP 高到低，每列含 `file`、`name`、`start`、`end`、`complexity`、`coverage`、`crap`、`over`、`advice`（`split`、`cover` 或 `null`）、`need_coverage`（百分比整數或 `null`））；`untouched_over`（加 `--base` 時沒改到但超標的函式數，不加時是 `null`）。

`mutation` 區塊：`kill_rate_threshold`、`reach_rate_threshold`、`exclude_mutators`；`counts`（八種狀態都要有）；`kill_rate`、`reach_rate`（百分比或 `null`）；`packages`（鍵是檔案所在目錄，用 `/` 分隔，根目錄是 `.`，值是八種狀態的計數）；`mutants`（篩過的改壞版本，已填 `line_text`，狀態含 `EQUIVALENT`、`EXCLUDED_MUTATOR`）；`unused_equivalents`（排除清單裡沒用到的項目，原樣）。`mutation --base` 時沒有改到任何原始碼檔案：不啟動檢查員，`mutants` 是空的，`inspector.tools` 是 `{}`、`inspector.settings` 是 `null`。

驗證函式是 `referee.schema.validate(報告)`，回傳錯誤訊息串列；欄位多或少都算錯。

## 設定檔 `.referee.json`（version 1）

```json
{
  "version": 1,
  "base": "origin/main",
  "gates": ["test", "crap", "mutation"],
  "sources": ["**/*.go"],
  "tests": ["**/*_test.go"],
  "exclude": ["vendor/", "tools/"],
  "test": {"command": ["go", "test", "./..."]},
  "crap": {"threshold": 12, "inspector": ["python", "tools/referee/inspectors/go.py", "functions"]},
  "mutation": {"kill_rate_threshold": 80, "reach_rate_threshold": 50,
               "exclude_mutators": [], "equivalents_file": ".referee-equivalents.json",
               "inspector": ["python", "tools/referee/inspectors/go.py", "mutants", "--workers", "4"]}
}
```

| 鍵 | 預設 | 規則 |
|---|---|---|
| `version` | 必填 | 必須是 1 |
| `base` | `origin/main` | 非空字串，`check` 的預設比較基準 |
| `gates` | 三關都啟用 | `test`、`crap`、`mutation` 的子集合，不能重複；順序固定是 test → crap → mutation |
| `sources`、`tests`、`exclude` | `[]` | 字串陣列。`gates` 有 `crap` 或 `mutation` 時，`sources` 至少要有一個樣式 |
| `test.command` | 無 | 字串陣列，不經過 shell。`gates` 有 `test` 時必填 |
| `crap.threshold` | 12 | 數字 |
| `crap.inspector` | 無 | 非空字串陣列。`gates` 有 `crap` 時必填 |
| `mutation.kill_rate_threshold` | 80 | 數字 |
| `mutation.reach_rate_threshold` | 50 | 數字 |
| `mutation.exclude_mutators` | `[]` | 字串陣列 |
| `mutation.equivalents_file` | `.referee-equivalents.json` | 非空字串 |
| `mutation.inspector` | 無 | 非空字串陣列。`gates` 有 `mutation` 時必填 |

未知的鍵、型別不對都是結束碼 2，不默默用預設值。語言特有的選項（例如 Go 的 `coverage_scope`）寫在 `inspector` 指令的參數裡，裁判不認得也不需要認得。

## 指令與結束碼

```
python referee.py test [--json 檔名]
python referee.py crap [--base B] [--json 檔名]
python referee.py mutation [--base B] [--json 檔名]
python referee.py check [--base B] [--skip 關...] [--json 目錄]
```

在專案根目錄執行，設定檔是 `.referee.json`。

| 結束碼 | 意思 |
|---|---|
| 0 | 通過（單獨執行的那一關不在 `gates` 裡：印「還沒啟用」，有 `--json` 就寫 `skipped` 的報告，也是 0） |
| 1 | 沒過門檻（單元測試沒過、CRAP 超標、抓錯率或測到率低於門檻） |
| 2 | 量測失敗或設定、記分表有誤（檢查員結束碼非 0、記分表沒寫出來或格式錯、設定檔錯、找不到 base 的分岔點、指令不存在） |

`check` 依序跑已啟用、沒被 `--skip` 的關，第一個沒過就停。`check --json 目錄` 每一關各寫一份報告：`test.json`、`crap.json`、`mutation.json`。跑了的關 `result` 是 `pass` 或 `fail`；沒啟用或被 `--skip` 的關照樣寫檔，`result` 是 `skipped`，`inspector`、`crap`、`mutation` 都是 `null`；`check` 停下之後，後面沒跑到的關不寫檔。
