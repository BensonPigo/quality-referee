# 教材

給人看的：三道關為什麼要有、每一關在量什麼。實際把 quality-referee 掛進專案，看 repo 根目錄的 [README.md](../README.md)。

## 閱讀順序

| 順序 | 文件 | 給誰看 | 內容 |
|---|---|---|---|
| 1 | [企業級AI代理人品質驗證與自動化防線架構指南.md](企業級AI代理人品質驗證與自動化防線架構指南.md) | 決定要不要導入的人、主管 | 為什麼 AI 寫的程式要靠機器量測把關，三道關各自擋什麼 |
| 2 | [01_單元測試/](01_單元測試/README.md) | 開發者 | 第一關：測試是考卷，程式是答案卷；附 Go 範例和練習 |
| 3 | [02_CRAP指標/](02_CRAP指標/README.md) | 開發者 | 第二關：CRAP 怎麼從複雜度和覆蓋率算出來；附 Go 範例和練習 |
| 3a | [02_CRAP指標/補充_圈複雜度.md](02_CRAP指標/補充_圈複雜度.md) | 想知道 C 怎麼算的人 | CRAP 公式裡的 C，用範例實際算一次 |
| 3b | [02_CRAP指標/補充_認知複雜度.md](02_CRAP指標/補充_認知複雜度.md) | 想比較另一種複雜度的人 | 認知複雜度的計分規則，和圈複雜度的差別；先讀 3a |
| 4 | [03_變異測試/](03_變異測試/README.md) | 開發者 | 第三關：故意把程式改壞，看測試抓不抓得到；附 Go 範例和練習 |
| 5 | [導入步驟_三道檢查.md](導入步驟_三道檢查.md) | 負責導入的人 | 在開發到一半的系統一關一關導入，技術債怎麼處理 |

01～03 的範例各自是獨立的 Go 模組（各有 `go.mod`），在該目錄執行 `go test ./...` 就能跑，跟 quality-referee 本身的程式無關。

這些文件講的是觀念，用的是通用的工具名稱（gocyclo、gremlins、Stryker 等）。quality-referee 怎麼把這些量測接成「裁判」和「檢查員」，見根目錄 README 的「誰扮演什麼角色」。
